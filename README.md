## :dart: O guia para alavancar a sua carreira

> Apache Wicket é um framework Java open source para construir aplicações web usando componentes orientados a objetos, sem misturar lógica de negócio com HTML — você escreve páginas em Java puro e as amarra a templates HTML simples, quase sem tags proprietárias. Criado em 2004 e hoje um projeto top-level da Apache Software Foundation, o Wicket ainda recebe releases frequentes (a série 10.x roda sobre Java 17+) e sustenta sistemas corporativos, de governo e de código aberto — como o GeoServer — que continuam em produção. Este guia é voltado principalmente para quem **já programa em Java** e precisa manter, evoluir ou entender um sistema legado em Wicket, ou para quem está migrando um projeto antigo para versões mais novas do framework. Por ser uma tecnologia de nicho, com comunidade pequena hoje, este guia é mais enxuto que os outros do Guia Dev Brasil — e é honesto sobre isso: priorizamos a documentação oficial, o código-fonte real das extensões (wicketstuff) e os poucos materiais de qualidade que existem, em vez de inflar a lista com links fracos ou repetidos.

## 🗺️ Roadmap

Não existe um roadmap de terceiros (como o roadmap.sh) dedicado a Apache Wicket — é um framework específico demais para isso. O caminho abaixo segue a estrutura do próprio [Guia do Usuário oficial](https://nightlies.apache.org/wicket/guide/10.x/single.html) e da [introdução em slides](https://wicket.apache.org/learn/presentations/wicketIntroduction.pdf) mantida pelo projeto.

**Pré-requisito:** Wicket não é para quem está começando em programação — ele pressupõe Java sólido (classes, interfaces, generics, Maven/Gradle) e noções de Servlets/JSP. Se você ainda não sabe Java, comece pelo [Guia de Java](https://github.com/arthurspk/guiadejava) do Guia Dev Brasil.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos do modelo de componentes** — entenda a diferença entre a abordagem do Wicket (componentes com estado, sem templating na marcação) e frameworks baseados em request/response como Servlets puros ou Spring MVC.
2. **Primeira aplicação** — gere um projeto com o [QuickStart oficial](https://wicket.apache.org/start/quickstart.html) e rode o `HelloWorld` dos [exemplos oficiais](https://wicket.apache.org/learn/examples/index.html).
3. **Markup e componentes** — como o Java se liga ao HTML via `wicket:id`, herança de markup e fragmentos.
4. **Models** — `IModel`, `PropertyModel`, `CompoundPropertyModel` e como o Wicket gerencia o ciclo de vida de dados por página/sessão.
5. **Formulários e validação** — `Form`, `FormComponent`, validadores embutidos e customizados.
6. **Ajax** — `AjaxLink`, `AjaxFormComponentUpdatingBehavior` e atualização parcial de página sem escrever JavaScript manualmente.
7. **URLs e navegação** — `PageParameters`, bookmarkable pages e mount de URLs amigáveis.
8. **Integração** — Spring, CDI/Java EE e testes com `WicketTester`.
9. **Produção** — deploy, configuração de `DEPLOYMENT` mode e, se for o caso, migração de uma versão antiga (6.x/7.x) para a série 10.x com os [guias de migração oficiais](https://s.apache.org/wicket10migration).

## 🔤 Sites e cursos para aprender Wicket

Este é o ponto mais fraco do ecossistema hoje: não existem cursos em vídeo ativos, gratuitos ou pagos, dedicados a Apache Wicket — nem em português, nem em inglês, nas plataformas que verificamos (Udemy, Pluralsight, Alura, Coursera, edX). O que existe de fato é a documentação oficial (seção acima), os livros (seção abaixo) e o código de exemplo mantido pela comunidade. Tratamos isso como um curso "de fato": siga o Guia do Usuário oficial capítulo a capítulo e rode os exemplos do repositório abaixo em paralelo.

> Cursos e materiais estruturados (o que existe hoje)

- [Wicket User Guide 10.x](https://nightlies.apache.org/wicket/guide/10.x/single.html) — Na prática, é o "curso" oficial e mais completo: do primeiro componente até integração com Spring e testes. Gratuito, mantido pela Apache.
- [Wicket-tutorial-examples (bitstorm)](https://github.com/bitstorm/Wicket-tutorial-examples) — Código-fonte de todos os exemplos usados no Guia do Usuário oficial, organizado por capítulo. Rode junto com a leitura do guia. Gratuito.
- [Exemplos ao vivo do Wicket](https://wicket.apache.org/learn/examples/index.html) — HelloWorld, formulários, Ajax, herança de markup e outros exemplos oficiais com código-fonte linkado.
- [modern-webdev-wicket (bitstorm)](https://github.com/bitstorm/modern-webdev-wicket) — Exemplos de uma aplicação Wicket moderna rodando sobre Servlet 3.x com Spring, incluindo uma abordagem mais atual de configuração. Gratuito.
- [Instant Apache Wicket 6 (Packt)](https://wicket.apache.org/learn/books/iaw6.html) — Livro curto e direto ao ponto, funciona como um curso rápido de introdução (54 páginas). Pago; ver detalhes na seção Livros.

## 📚 Livros

Praticamente todos os livros sobre Wicket foram escritos entre 2006 e 2015 — é um reflexo real da idade do framework, não uma lacuna de pesquisa. Ainda assim, os fundamentos de componentes e models mudaram pouco, e os títulos abaixo continuam sendo a referência mais aprofundada disponível.

- [Wicket in Action (Martijn Dashorst e Eelco Hillenius)](https://wicket.apache.org/learn/books/wia.html) — O livro de referência da Manning, escrito por dois dos criadores do framework. Cobre desde componentes básicos até Ajax, Spring e Hibernate. Pago (disponível também na [página da Manning](https://www.manning.com/books/wicket-in-action)).
- [Apache Wicket Cookbook (Igor Vaynberg)](https://wicket.apache.org/learn/books/awc.html) — Formato de receitas práticas da Packt, cobrindo Wicket 1.4/1.5. Pago.
- [Instant Apache Wicket 6 (João Sávio Ceregatti Longo e Felipe Fedel Pinto)](https://wicket.apache.org/learn/books/iaw6.html) — Livro curto da Packt escrito por dois autores brasileiros, focado em colocar você produtivo rápido com o Wicket 6. Pago.
- [Pro Wicket (Karthik Gurumurthy)](https://wicket.apache.org/learn/books/prowicket.html) — Um dos primeiros livros sobre o framework (Apress), cobrindo Wicket 1.2, incluindo integração com Spring e Ajax. Pago.
- [Enjoying Web Development with Wicket (Kent Tong)](https://wicket.apache.org/learn/books/ewdww.html) — Livro autopublicado e extenso (~400 páginas), cobrindo as séries 6.x e 7.x. Em inglês, pago.
- [Wicket: Komponentenbasierte Webanwendungen in Java](https://wicket.apache.org/learn/books/kwij.html) — Livro em alemão sobre desenvolvimento de aplicações com Wicket. Útil se você lê alemão ou quer usar tradução automática como apoio.
- [Komponentenbasiert und objektorientiert — das alternative Java-Webframework](https://wicket.apache.org/learn/books/koda.html) — Outro título em alemão sobre a abordagem orientada a componentes do Wicket.
- [Praxisbuch Wicket](https://wicket.apache.org/learn/books/praxisbuchwicket.html) — Livro prático em alemão, focado em exemplos de uso do dia a dia com o framework.
- [Livro sobre Wicket em japonês](https://wicket.apache.org/learn/books/wicket-jp.html) — Material em japonês listado oficialmente pelo projeto, para quem lê o idioma.

## 🧪 Projetos práticos e código real

- [GeoServer](https://github.com/geoserver/geoserver) — Servidor geoespacial open source com milhares de estrelas cuja interface administrativa é construída em Wicket; código de produção real, em manutenção ativa.
- [Apache Causeway (ex-Apache Isis)](https://causeway.apache.org/) — Framework para aplicações orientadas a domínio que usa o Wicket como um de seus viewers de UI — bom exemplo de Wicket "por baixo" de outra abstração.
- [ProjectForge](https://www.projectforge.org/) — Sistema open source de gestão de projetos e horas construído em Wicket, com código-fonte aberto para estudo.
- [Orienteer](https://github.com/OrienteerBAP/Orienteer) — Plataforma de CRM/CMS/ERP construída sobre Wicket e OrientDB, com desenvolvimento ativo.
- [YesCart](https://github.com/inspire-software/yes-cart) — Plataforma de e-commerce open source com o painel administrativo escrito em Wicket, em manutenção ativa.

## 🤖 IA na prática

Wicket é um framework de nicho: os assistentes de IA foram treinados com muito menos código Wicket do que Spring, React ou Django, e isso muda como você deve usá-los.

**Para aprender**
- Cole um trecho de um `PageParameters`, `IModel` ou `Form` e peça para a IA **explicar o ciclo de vida do componente** — mas depois confirme cada afirmação no [Guia do Usuário oficial](https://nightlies.apache.org/wicket/guide/10.x/single.html), porque é comum a IA confundir o comportamento do Wicket com o de outro framework MVC.
- Peça para comparar um trecho de Wicket com o equivalente em Spring MVC ou JSF — ajuda a entender por que o Wicket faz as coisas de um jeito diferente (estado no servidor, sem template engine própria).
- Use a IA para **ler HTML de markup Wicket** (`wicket:id`, `wicket:child`, herança de markup) e explicar a que componente Java cada trecho se liga.

**Para trabalhar em sistemas legados**
- Use [GitHub Copilot](https://docs.github.com/pt/copilot), [Cursor](https://cursor.com/), [Claude Code](https://code.claude.com/docs/en/overview), [Gemini CLI](https://github.com/google-gemini/gemini-cli) ou o [JetBrains AI Assistant](https://www.jetbrains.com/ai/) (bom encaixe se você já usa IntelliJ para Java) para navegar bases de código Wicket antigas: peça um resumo da árvore de componentes de uma página, ou "encontre onde este `AjaxLink` é usado".
- A IA é útil para **migrar** de versões antigas (1.4, 1.5, 6.x) para a série 10.x: peça para comparar seu código com o [guia de migração oficial](https://s.apache.org/wicket10migration) e sinalizar APIs removidas ou renomeadas.
- Para gerar testes com `WicketTester`, dê à IA um exemplo real do [repositório de exemplos](https://github.com/bitstorm/Wicket-tutorial-examples) como referência de estilo antes de pedir novos testes — sem isso, ela tende a inventar métodos que não existem na API de teste do Wicket.

**Limites e boas práticas**
- A IA **alucina APIs do Wicket com muito mais frequência** do que em frameworks populares — nomes de métodos plausíveis que não existem, comportamento de `IModel` incorreto, confusão entre `Component#onConfigure` e `onBeforeRender`. Sempre confira contra o [JavaDoc oficial](https://nightlies.apache.org/wicket/apidocs/10.x/index.html).
- Antes de aceitar uma sugestão que envolve serialização (Wicket serializa componentes na sessão), confirme que classes/campos são `Serializable` — é uma fonte clássica de bugs em produção que a IA costuma ignorar.
- Não cole código-fonte de sistemas internos/proprietários em ferramentas sem a política de segurança da sua empresa — muitos sistemas em Wicket são legados de instituições públicas ou financeiras com regras de compliance rígidas.
- Trate a IA como assistente de leitura e migração, não como autoridade sobre a API — a documentação oficial e o código-fonte do próprio Wicket (aberto no GitHub) são as fontes de verdade.

## 💼 Carreira e vagas

Seja honesto com suas expectativas: hoje quase não existem vagas que pedem Wicket como requisito principal — é majoritariamente uma tecnologia de manutenção de sistemas legados (governo, financeiro, ERPs internos), não de novos projetos. Ainda assim, aparece ocasionalmente como "diferencial" em vagas de Java sênior, e algumas empresas prestam suporte comercial ao framework.

- [Empresas que oferecem suporte comercial ao Wicket](https://cwiki.apache.org/confluence/display/WICKET/Companies+that+provide+services) — Lista oficial mantida pelo projeto; útil tanto para quem procura serviço quanto para quem procura trabalhar com Wicket profissionalmente.
- [backend-br/vagas](https://github.com/backend-br/vagas) — Vagas de back-end no Brasil publicadas como issues no GitHub; use a busca do repositório para filtrar por "Java" ou "Wicket".
- [Vagas de Java no ProgramaThor](https://programathor.com.br/jobs-java) — Vagas de Java no Brasil, com faixa salarial informada; ocasionalmente aparecem vagas de manutenção de sistemas Wicket.
- [GeekHunter](https://www.geekhunter.com/pt) — Plataforma de recrutamento tech brasileira em que as empresas procuram você — útil para perfis de Java sênior com experiência em frameworks legados.
